# Bugfix: 投资计划列表接口 (/api/plan/list) 返回 500 错误

## Bug 描述
在查询投资计划历史列表时，后端接口返回 `500 Internal Server Error`，前端提示“系统繁忙”。

## Bug 原因
1. **空指针/枚举解析异常**：在将数据库实体 `InvestmentPlan` 转换为 `InvestmentPlanVO` 时，如果 `risk_level` 或 `status` 字段为 null，调用 `toLowerCase()` 或枚举工具类会触发异常。
2. **环境冲突 (JDK)**：后端项目要求的 JDK 版本为 21，但测试环境默认使用了 JDK 8，导致部分字节码兼容性问题及编译错误。
3. **全局异常掩盖**：`GlobalExceptionHandler` 捕获了所有异常并返回统一的“系统繁忙”，掩盖了真实的堆栈信息，增加了排查代码逻辑错误的难度。

## 解决方案
1. **增强健壮性**：在 `InvestmentPlanServiceImpl.getHistory` 方法中对 `riskLevel` 和 `status` 字段增加非空校验，并提供默认值（如 `balanced` 和 `draft`）。
2. **环境修复**：修正 `JAVA_HOME` 指向 JDK 21 路径，并重新编译。
3. **透出错误信息**：修改 `GlobalExceptionHandler`，在开发调试阶段透出具体的 `e.getMessage()`，便于定位。

## 学习总结
1. 对于数据库选型为 `VARCHAR` 的字段，Java 代码中必须做好 `null` 防护。
2. 统一返回对象（Result）虽然好，但全局异常处理器不应在开发模式下完全吞掉错误详情。
