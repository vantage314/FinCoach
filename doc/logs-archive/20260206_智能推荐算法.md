# 2026-02-06 智能投顾推荐算法与闭环实现

## 1. 核心目标
将原有的“通用型建议”（如：建议买入金融投资 1000 元）升级为“智能具体资产推荐”（如：基于激进型风险偏好，推荐买入纳指100ETF 1000 元），并打通从计划生成到资产执行的业务闭环。

## 2. 算法逻辑升级

### 2.1 风险等级映射
系统将用户风险评测得分映射为 5 个等级 (R1-R5)，每个等级对应不同的核心资产池策略：

| 风险等级 | 对应数据库 risk_level | 选股策略 | 标签 |
| :--- | :--- | :--- | :--- |
| 保守型 (Conservative) | R1 | 货币基金、国债 | 🛡️ |
| 稳健型 (Steady) | R2 | 银行理财、纯债基金 | 📈 |
| 平衡型 (Balanced) | R3 | 混合基金、宽基指数 | ⚖️ |
| 进取型 (Growth) | R4 | 行业指数、蓝筹股 | 🚀 |
| 激进型 (Aggressive) | R5 | 成长股、加密货币概念 | 🔥 |

### 2.2 智能选股 (pickSecurities)
- **输入**：用户风险等级 (UserRiskProfile)
- **处理**：
  1. 查询 `market_security` 表。
  2. 过滤 `risk_level` <= 用户风险等级 (向下兼容，但优先匹配同级)。
  3. 按 `change_percent` (年涨幅) 降序排列。
  4. 选取 Top 2-3 只表现最优的资产。
- **输出**：具体资产列表 (MarketSecurity)。

### 2.3 计划生成策略
- **增量模式 (Contribution)**：
  - 计算各分类缺口。
  - 若“金融投资”类有缺口，调用 `pickSecurities` 获取推荐资产。
  - 将缺口资金平均分配给推荐资产。
  - 生成 `PlanItemVO`，其中 `subType` 存储资产名称，`reason` 包含动态生成的推荐语。
- **存量模式 (Rebalance)**：
  - 计算当前持仓与目标比例的偏差 `diff`。
  - 若偏差绝对值 > `MIN_THRESHOLD` (1000元)，触发调整。
  - 卖出逻辑：查找该分类下金额最大的单项资产进行削减。

## 3. 业务闭环
交互流程如下：
1. **生成**：前端输入金额 -> 后端计算缺口 & 匹配资产 -> 返回预览列表。
2. **确认**：用户查看具体资产与理由 -> 保存计划 (状态: PENDING)。
3. **执行**：在详情页点击“一键执行” -> 后端事务开启。
   - 遍历 `PlanItem`。
   - `BUY`：插入 `AssetItem`，命名规则 `新入库-[资产名]-[日期]`。
   - `SELL`：扣减现有大额资产余额。
   - 更新计划状态为 `EXECUTED`。
