# Alerts & Admin V1 (2026-02-18)

## Context
We need a minimal but operable alert loop that can be generated from HealthReportV2, stored, queried, acknowledged, and audited without adding new dependencies or schema changes.

## Alert Rules & Config Keys
Alerts are generated by AlertEngineV1 after each report. Rules are configurable via score rule params (fallback to defaults when missing, with warnings).

Codes:
- `ALERT_RISK_HIGH`: riskScore level HIGH or value >= `ALERT_RISK_HIGH_MIN`
- `ALERT_MDD_HIGH`: maxDrawdown > `ALERT_MDD_HIGH`
- `ALERT_REBAL_TRIGGERED`: rebalanceAdviceV1.triggered = true
- `ALERT_CASHFLOW_NEGATIVE`: monthlySurplus < 0
- `ALERT_EMERGENCY_FUND_LOW`: emergencyFundMonths < `EMERGENCY_MONTHS_LOW`
- `ALERT_DTI_HIGH`: dti >= `DTI_HIGH`
- `ALERT_DEBT_TO_ASSETS_HIGH`: debtToAssets > `DEBT_TO_ASSETS_HIGH`
- `ALERT_INSURANCE_GAP_HIGH`: insurance summaryLevel HIGH or topGapValue > `ALERT_INSURANCE_GAP_VALUE_MIN`

Enable toggles (bool):
- `ALERT_RISK_HIGH_ENABLED`
- `ALERT_MDD_HIGH_ENABLED`
- `ALERT_REBAL_TRIGGERED_ENABLED`
- `ALERT_CASHFLOW_NEGATIVE_ENABLED`
- `ALERT_EMERGENCY_FUND_LOW_ENABLED`
- `ALERT_DTI_HIGH_ENABLED`
- `ALERT_DEBT_TO_ASSETS_HIGH_ENABLED`
- `ALERT_INSURANCE_GAP_HIGH_ENABLED`

Severity mapping (string: INFO/WARN/CRITICAL):
- `ALERT_RISK_HIGH_SEVERITY`
- `ALERT_MDD_HIGH_SEVERITY`
- `ALERT_REBAL_TRIGGERED_SEVERITY`
- `ALERT_CASHFLOW_NEGATIVE_SEVERITY`
- `ALERT_EMERGENCY_FUND_LOW_SEVERITY`
- `ALERT_DTI_HIGH_SEVERITY`
- `ALERT_DEBT_TO_ASSETS_HIGH_SEVERITY`
- `ALERT_INSURANCE_GAP_HIGH_SEVERITY`

Other thresholds:
- `ALERT_RISK_HIGH_MIN` (default 70)
- `ALERT_MDD_HIGH` (default 0.30)
- `ALERT_INSURANCE_GAP_VALUE_MIN` (default 100000)

## Storage Strategy (A)
Use existing `fc_alert_record` table. Each generated alert is inserted with:
- `ruleKey` = alert code
- `severity` = mapped severity
- `message` = title
- `status` = OPEN
- `payloadJson` includes reportId/code/detail/related

ACK updates `status` to `ACKED`.

## Admin API
List:
```
GET /admin/api/alerts?limit=200&status=OPEN|ACKED|ALL
```
Ack:
```
POST /admin/api/alerts/ack
{
  "alerts": [{"alertId": 123}]
}
```
Alternative ack:
```
POST /admin/api/alerts/ack
{
  "reportId": 1001,
  "codes": ["ALERT_RISK_HIGH", "ALERT_DTI_HIGH"]
}
```

Export (no endpoint):
- Use `AlertExportUtil.toCsv(items)` on the list response to generate CSV.

## How To Verify
- `cd backend && mvn clean test`
- Generate a report and confirm `metrics.alertsV1` exists and `event=ALERT_V1` appears in logs.
- `curl` examples:
  - `curl -s "http://localhost:8080/admin/api/alerts?limit=10&status=OPEN"`
  - `curl -s -X POST "http://localhost:8080/admin/api/alerts/ack" -H "Content-Type: application/json" -d '{"alerts":[{"alertId":1}]}'`
