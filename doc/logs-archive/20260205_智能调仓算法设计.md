## 1. 再平衡算法 (Rebalancing Algorithm)

### 核心公式
- **存量模式 (REBALANCE)**: `Diff = Total_Current * TargetRatio - CurrentHoldings`
- **增量模式 (CONTRIBUTION)**: `Diff = (Total_Current + New_Money) * TargetRatio - CurrentHoldings`

### 增量再平衡 (Inflow Rebalancing) 逻辑
1. **目标计算**: 确定新资金注入后的目标总额。
2. **缺口分析**: 计算各分类在达到目标比例时的资金缺口 `Gap = TargetAmount - CurrentHoldings`。
3. **优先级分配**:
   - 优先填补 `Gap > 0` 的类目（即当前配比较低的类目）。
   - 尽量不建议卖出 (SELL)，除非某一类资产严重超出目标比例（例如超过目标 20% 以上）。
4. **话术优化**: 针对新资金，使用引导性话术（如：“建议将这笔闲钱投入...以补足缺口”）。

### 触发阈值
| 参数 | 值 | 说明 |
|:---|:---:|:---|
| MIN_THRESHOLD | ¥1,000 | 最小操作金额，防止建议买 1 块钱 |

### 生成逻辑
```
IF Diff > MIN_THRESHOLD:
    生成 BUY 建议
ELSE IF Diff < -MIN_THRESHOLD:
    生成 SELL 建议
ELSE:
    不生成建议（已接近目标）
```

## 7. 自动执行逻辑 (Auto-Execution Logic)

### 命名规则 (Auto-Naming Rule)
- **新购资产**: `新入库-[子类]-MMdd` (例如：`新入库-股票基金-0205`)。
- **目的**: 方便用户一眼识别出哪些资产是通过智能建议系统自动生成的。

### 减持策略 (Sell-Down Strategy)
- **资产定位**: 自动查找该分类下“当前价值最大”的资产记录进行扣减。
- **风险控制**: 
  - 若最大单笔资产余额不足，系统将抛出异常并提示用户“需手动处理”，防止出现负资产。
  - 核心逻辑包裹在 `@Transactional` 事务中，确保“扣减”与“计划状态更新”的原子性。

### 全链路刷新 (Full-Link Refresh)
- **联动机制**: 执行完成后，前端通过 `emit('success')` 触发 `Dashboard` 全量刷新（资产列表、健康分、组合汇总），实现即时反馈。
