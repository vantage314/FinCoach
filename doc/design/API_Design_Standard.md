# API 设计标准文档

## 1. 核心原则
所有新开发的 Web 接口必须遵循本标准化要求，以确保系统具有良好的可维护性和自动文档生成能力。

## 2. 注解强制规范
- **控制器层 (Controller)**:
    - 必须使用 `@Tag` 注解说明该控制器的职责。
    - 示例: `@Tag(name = "模块名称", description = "模块详细描述")`
- **业务方法**:
    - 必须使用 `@Operation` 注解说明接口的功能。
    - 示例: `@Operation(summary = "简短总结", description = "详细功能的描述")`
- **参数与 DTO**:
    - 复杂对象参数必须使用 `@Schema` 描述每一个字段。
    - 示例: `@Schema(description = "字段含义", example = "示例值")`

## 3. 响应封装规范
- 所有接口必须统一使用 `Result<T>` 进行封装返回。
- 禁止直接返回实体类或裸数据。
- 状态码定义：
    - `200`: 成功
    - `401`: 未授权 (身份认证失败)
    - `403`: 无权限
    - `500`: 服务器内部错误

## 4. 路径命名规范
- 使用 RESTful 风格，路径全小写，多单词间使用 `-` 连接（kebab-case）。
- 基础路径统一以 `/api` 开头。
