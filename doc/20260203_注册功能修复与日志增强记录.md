# 20260203_注册功能修复与日志增强记录

## 1. 问题分析
- **现象**: 前端显示注册成功，但数据库 `user` 表中无数据。
- **原因判定**: 
    - 之前的后端版本中 `AuthController` 仅为占位逻辑，并未调用数据库。
    - 在补全 Service 与 Mapper 后，由于 JDK 版本冲突及 IDE 索引失效，新代码编译失败，导致后端启动的仍是旧版本的 `.class` 文件。
    - 数据库 `create_time` 与 MyBatis Plus 自动生成的逻辑可能存在匹配问题。

## 2. 修复与增强内容
### 2.1 配置层面 (Step 1)
- **SQL 日志**: 在 `application.yml` 中开启了 `StdOutImpl`，现在控制台会清晰打印每一条 `INSERT` 语句及影响行数。
- **路径确认**: `logging.file.name` 已确认生产日志存放于 `../log/backend/fincoach.log`。

### 2.2 逻辑层面 (Step 2 & 3)
- **日志注入**: 
    - `AuthController` 增加请求进入日志。
    - `AuthServiceImpl` 增加插入执行前后日志，包含插入行数校验。
    - `GlobalExceptionHandler` 增加 `log.error` 堆栈打印，方便定位 SQL 语法或连接错误。
- **注解校验**: 已确认 `User` 实体类具备 `@TableName("user")` 和 `@TableId(type = IdType.AUTO)`。
- **扫描路径**: `CoreApplication` 的 `@MapperScan` 已更新为 `com.fincoach.core.repository` 宽路径扫描。
- **手动补全时间**: 显式设置 `setCreateTime(LocalDateTime.now())` 以确保数据落盘。

## 3. 验证步骤
1. 执行 IDE 的 **Rebuild Project**。
2. 启动 `CoreApplication`。
3. 通过 Swagger 或前端再次注册。
4. 观察控制台输出 `INSERT INTO user ...`。
